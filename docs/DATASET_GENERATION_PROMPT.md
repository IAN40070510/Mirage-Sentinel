# 給 GPT-5.6 Sol 的資料集生成提示詞

將以下內容貼到可存取 Mirage-Sentinel 專案的工作階段。先以小批次確認規格，不要直接生成大量近似資料。

---

你是 Mirage-Sentinel 專題的資料工程協作者。請先閱讀 AGENTS.md、services/commerce/detection.py、model/commerce/features.json、scripts/smoke_commerce.py、commerce/apps/backend 的實際 API 與 storefront 操作程式，確認你所在目錄是包含 .git 的正確工作副本。不要覆蓋尚未提交的變更。

目標：為保護 Medusa／DTC 電商的 XGBoost 建立可追溯的 HTTP 請求資料集。先生成少於 20 筆的樣本檔與資料規格，確認後才擴大。不要在這個階段擅自更換推論介面、訓練模型、部署或推送 GitHub。

## 類別與邊界

第一版固定五類：normal、sqli、xss、cmdi、path_traversal。排除 SSTI；SSRF 暫不加入，待實際 URL 抓取端點與標註情境確定。不要增加 anomaly／other 來收納無法判定的資料。

- normal：正常瀏覽、搜尋、會員、購物車、下單，也包括合法重試、拼字錯誤、搜尋無結果、庫存不足、放棄結帳等。特殊符號、單引號、網址與程式碼文字不自動等於攻擊。
- sqli：情境中企圖改變 SQL 查詢語意的輸入，不是單純出現 SQL 詞彙。
- xss：情境中企圖將輸入變成瀏覽器可執行內容，不是所有 HTML 文字。
- cmdi：情境中企圖注入伺服器系統命令，不是單純出現分號或命令名稱。
- path_traversal：企圖越過允許目錄邊界的檔案路徑操作。不要直接將所有 LFI 或檔案存取視為此類。

攻擊標籤表示嘗試，不聲稱 Medusa 存在對應漏洞或利用成功。優先生成只有一個明確類型的樣本；多類或不確定樣本放入待審清單，不要強塞答案。攻擊工作階段中的正常瀏覽仍應逐筆標為 normal。

## 資料採集

不區分 AI 與真人來源。離線生成或實際操作採集的差異只記錄在批次說明文件；不得把生成資料冒充已執行的流量紀錄。

沒有實際執行工具或可用測試環境時，只生成離線樣本並列出未驗證事項。真正採集時只使用明確指定的本機隔離測試目標；不要對公開 OCI 或第三方網站發送攻擊。先用測試 API 讀取商品、variant、region、配送選項等實際 ID，不猜測。保留 mock／placeholder 與實測資料的明確區分。

正常樣本須包含瀏覽器與 API 客戶端；攻擊樣本亦然。避免用 User-Agent、固定 header、固定帳號或時間等來源線索區分正常與攻擊。生成內容不得含真實憑證或真人個資。

## 格式

輸出 UTF-8 JSONL。不新增 source、annotation（含 reason、review_status、reviewer）、outcome、scenario_id 或 session_id 欄位。

每筆資料包含：
- sample_id：每筆請求的唯一編號，用於追查樣本及誤判結果，必填。
- template_family：使用模板生成變形樣本時必填的家族名稱；相同模板只改大小寫、編碼或數字，仍使用同一家族。非模板資料可省略或為 null。
- request：method、path、query、headers、body。query 保存原始編碼；body 用字串或 null，保存待傳送內容，不能自動把 form 改成 JSON。
- label：五類之一，作為訓練目標 y。

不新增情境 ID 欄位。測試情境以文字記錄在批次說明文件即可。

sample_id、template_family、label 都不是模型特徵。X 只能由分流當下可取得的請求與可重現的歷史資訊形成；y 是 label。不得讓訓練程式把整個 JSONL 欄位盲目串成文字。

實際採集時另存關聯 sample_id 的執行紀錄，包含毫秒時間戳、實際送出請求、response_status、route、response_origin、latency_ms。回應、分流結果及模型自己的預測不能當成人工正確答案，也不能作為事前分類特徵。

Cookie／Authorization 不保存可重用的秘密，不使用登入憑證作為樣本分組依據。任何正規化或遮罩，都要記錄版本。路徑穿越等案例須確認客戶端實際送出的路徑，避免自動正規化改掉待測輸入。

## 初始交付

先產出 15 筆：normal 7 筆，其餘四類各 2 筆。正常樣本至少包含合法特殊符號、搜尋無結果情境與不同正常操作。若購物操作缺少實際 ID，明確標示為未驗證範本，不能聲稱已完成下單。攻擊案例避免破壞、資料外傳或外部回呼，使用無害驗證內容。

同時交付資料字典、標註規則、各類樣本數統計、JSONL 格式檢查與重複樣本檢查結果。這 15 筆只供格式審查，不分割成訓練／驗證／測試，也不報告模型成績。

## 後續擴大時的要求

目標切分比例可先設 70/15/15，但要依非空的 template_family 與近似樣本分組，防止跨集合洩漏；報告實際比例及各類數量。同一模板家族及近似樣本必須留在同一集合，跨組有關聯時合併分組。缺少 template_family 時仍須檢查近似樣本，不可把所有 null 視為同一群組。實際操作若按完整流程分檔採集，同一流程檔案應整份放入同一集合；若無法還原流程關聯，須在報告註明不能保證工作階段間獨立，不宣稱已完成工作階段層級的切分或評估。TF-IDF 等需要 fit 的步驟只能使用訓練集。

保留獨立的實際操作測試情境；缺少實測資料時列為待收集，不得補造執行紀錄。測試集不得參與調參。記錄提示詞版本、隨機種子（若適用）、程式版本、檔案 SHA-256 及去重前後數量。

未來訓練須輸出多分類與合併正常／攻擊的兩種混淆矩陣、各類 precision/recall/F1/support、Macro-F1、正常誤報率、攻擊漏判率與逐筆預測。另比較規則、模型、規則加模型；不足以計算的指標標示無法計算，不捏造數值。

程式與模型包須可從 Windows 搬到 Linux ARM64。使用 pathlib、CLI 或環境變數設定目錄，不寫死使用者路徑；推論不能依賴原始資料集或訓練目錄。禁止 pickle。模型、詞彙表／IDF、特徵順序、類別映射與版本須作為一致的部署包，不能只改舊模型標籤表。
