# 誤判與推論覆蓋修補 v6（2026-11-01）

本版重新訓練五分類 XGBoost，採用 enforce 模式。修復已重現的正常搜尋誤判、JSON 跳脫偵測缺口及並行請求略過模型問題。新保留正常資料驗收通過；GitHub 整合與正式部署結果另見 deployment-status.json。模型與服務規則的成績分開揭露。

## 根因與修正

1. **資料分布捷徑**：原始正常資料幾乎只有 GET；購物流程補強後，複雜搜尋仍集中於少數固定分頁格式。同一個「日本製」舊模型分數可因加入分頁從 0.997230 變成 0.071356。詳見 root-cause-counterfactual.json。
2. **一般文字與攻擊語法混淆**：舊規則將 javascript:、UNION SELECT、../../ 教材或圖樣文字直接視為攻擊。新規則檢查較完整語法，並保留實際可執行字串回歸。
3. **正常內容不足**：v3 剩下教材與圖樣誤判；v4 新增 sale >= 250／括號描述誤判；v5 剩下「幅 < 28」。逐步加入一般比較式、括號描述、多語言尺寸條件與同詞彙攻擊配對，v6 全部回歸通過。沒有建立正常詞彙白名單，也沒有針對單筆人工調高門檻。
4. **JSON 解碼不一致**：規則以前只看原始 JSON，無法正確辨認跳脫的 Windows 路徑。現在會有界解析 JSON 字串值，保留原文及解碼內容的檢查；另補 SQL 註解、SVG onload 與完整指令片段。
5. **並行略過模型**：原先 16 個同時請求中 15 個退回規則。現在採有容量與時間上限的推論佇列，實測 16/16 都完成模型判斷。超載或模型故障會回 503／Retry-After，不將訪客當攻擊，也不默默直接放行。逾時工作完成前仍保留鎖，避免無上限堆積背景推論。
6. **部署驗收不足**：就緒檢查原本只確認 API，現在連商店首頁一併確認。CI 對已知誤報、漏判與推論 fallback 會直接失敗。正式服務會比對實際載入的模型指紋。

鑑識資料仍走非同步佇列與 append-only collector；未讀取或清除正式鑑識資料，未變更容器隔離與權限配置。舊訪客的既有隔離狀態沒有批次解除。

## 仍須誠實揭露的限制

- 舊來源仍漏判 `c:windowswin.ini`，來源標為 path-traversal；該字串在原始 CSV 就缺少目錄分隔符。保留原標籤與漏判數，未刪除、改標或加精確字串規則。需人工確認來源標籤與應用情境，不能宣稱全部攻擊皆能辨識。
- 模型只使用 content-type header，其他 header 攻擊主要由服務規則偵測。五分類模型單獨對 39 筆診斷僅命中 17 筆，這是模型覆蓋限制，不能用系統合併結果掩蓋。
- 正常請求零誤報只成立於本次測試範圍。新的輸入分布、未見語法及真實流量仍可能誤判；本版沒有改為觀察模式。
- 舊 v3 曾通過較寬鬆標準但仍有 3 筆正常誤報，且 GitHub 在首頁驗收失敗，未部署。v4、v5 都因回歸失敗淘汰；本版另用未評分的保留池驗收。
- 訓練輸出的 rules 指標使用凍結的舊基準規則。實際服務規則的結果以 regression.json、previous-pool-regression.json 與 reserved-result.json 為準。
