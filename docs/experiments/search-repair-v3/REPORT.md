# 正常搜尋誤判根因與修補（2026-10-31）

## 根因證據

同一個搜尋值只改變分頁參數，就造成顯著不同的模型分數。舊模型對複雜字串與請求格式的交互關係過度敏感，先前應用正常搜尋只有少量固定格式；有涵蓋購物流程不等於涵蓋搜尋輸入。

| 搜尋 | 舊模型：只有 q | 舊模型：加 limit/offset | 新模型：只有 q |
|---|---:|---:|---:|
| 紅色上衣 | 0.909480 | 0.017225 | 0.000492 |
| 100% cotton | 0.963720 | 0.000735 | 0.101025 |
| C++ | 0.990426 | 0.031577 | 0.303317 |
| 日本製 | 0.997230 | 0.071356 | 0.000371 |

此外，固定規則只見 UNION SELECT、javascript: 或重複 ../ 就判攻擊，未區分完整攻擊語法與普通教材／圖樣文字。模型誤判與規則誤判是兩個不同原因。

## 實際修補

- 正常與攻擊同時加入只有 q、分頁在前／在後、排序參數、空白編碼、JSON note 等格式，避免某種格式被直接當作正常標籤。
- 新增正常訓練 3,191 筆、正常驗證 1,776 筆；其餘為同分割既有攻擊的合成格式變體。這些不是新的獨立攻擊或真實流量。所有來源、父樣本、生成程式雜湊都保留。
- 攻擊近似跨集合衝突與完全重複樣本排除；最終稽核衝突為零。
- 規則要求較完整 SQL 運算元／JavaScript 可執行語法／連續路徑內容，不以關鍵字白名單放行。原測試 25,000 筆攻擊中，新舊實際服務規則均命中 13,473 筆，沒有丟失既有規則命中。
- 保留 XGBoost 五分類、原特徵契約及 enforce 模式；沒有改成觀察模式或移除攻擊規則。

## 驗證結果與限制

- 已揭露的 26 筆正常邊界案例：原本 11 筆被模型或規則分流，修補後 0 筆。這是回歸，不是盲測。
- 原 60 個正常流程、2,160 筆請求重播：0 筆誤報、0 筆模型 fallback。
- 模型及規則凍結後才評估的新詞彙池：原始 2220 筆，排除 64 筆完全重複後，共 2156 筆；與開發資料完全重複 0 筆。誤報 3 筆（0.139%），各格式低於事前訂定 1% 門檻。
- 同批詞彙用固定舊模型與相同修補後規則比較：誤報 753/2156（34.926%）。此比較未訓練或調參。
- 舊來源測試五分類 Accuracy 99.9801%，Macro-F1 99.6959%。攻擊門檻漏報 2/25,000（0.008%），前版為 1/25,000；需揭露這個差異，不能說完全沒有代價。
- 新詞彙池仍由同一生成程式產生，是未參與訓練的詞彙與格式測試，不是實際使用者流量或未知攻擊驗收。
- 訓練報告內 rules 為原凍結基準；本次規則驗收與回歸使用實際服務 Detector，不將兩者混為一談。
