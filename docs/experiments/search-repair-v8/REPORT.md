# 正常請求與前端內部 API 修補 v8（2026-11-01）

本版重新訓練五分類 XGBoost，維持 enforce 直接判斷，並修補判斷與驗收缺口。模型和規則已凍結並通過新保留正常資料；實際部署以 GitHub Actions 的整合、模型指紋與購物隔離驗收紀錄為準，不以本地通過代替上線成功。

## 原設計與資料保護

Mirage、真實電商、沙盒電商、資料庫 schema、網路隔離、容器使用者與權限皆未修改。Compose 只更換唯讀模型掛載路徑，正式資料卷保留。鑑識資料仍由 collector 非同步 append-only 寫入，沒有讀取、刪除或重建鑑識資料庫。沒有批次解除既有訪客隔離。

模型忙碌時採有容量和時間上限的佇列；無法完成模型判斷時回 503／Retry-After，不將訪客誤標攻擊，也不直接放行到真實電商。規則可辨識的攻擊仍照原設計進入沙盒。沒有針對內部 API 加白名單或繞過模型。

購物驗收會唯讀查詢**自己這次測試訪客**的 `/state/visitors.db` 狀態，確認正常流程位於真實電商、攻擊後位於沙盒，再驗證兩邊訂單隔離。這是可拋棄狀態庫的測試檢查，沒有讀取 `/forensics/events.db`，也不新增公開查詢端點或修改資料庫。

## 找到的根因

- 原正常資料與補強流程漏掉前端伺服器端 API：分類、集合、購物車／訂單詳細欄位及商品查詢。瀏覽器側蒐集成功不代表已涵蓋這些內部請求。v6 對 288 筆來源程式衍生請求誤報 138 筆，GitHub 出現新訪客首頁 HTTP 500；沒有部署。
- 訓練路由加權未正規化 `reg_`、`pcol_` 等資源 ID，加入內部 API 後把 27 種正常路由誤算為 225 種；一般商品查詢獲得的正常類權重占比從應有的 3.70% 降為 0.44%。已補 ID 分組並加入回歸測試。此分組只影響訓練權重，模型輸入仍保留原始請求。
- 先前搜尋資料對分頁位置、空白編碼、中文／日文尺寸、括號、教材文字覆蓋不足。已使用正常／攻擊配對擴充；細節與舊版反事實證據保留於 v3／v6 歷史報告。
- 規則原先過度依賴關鍵字，另漏掉 JSON 跳脫內容、SQL 註解、SVG／HTML 事件及完整指令片段。修補時同時測試正常教材文字。追加的滑鼠事件 XSS 和 IIF 條件除零語法使用結構檢查，不以單筆測試字串當黑名單。
- 原推論忙碌時會略過模型；現採有界排隊，16 筆並行皆完成模型。原就緒檢查重用 cookie，可能接受已被隔離的訪客；現在每次重試使用新訪客。CI 會對回歸失敗直接阻止部署，失敗時保存有界、遮蔽敏感值的容器錯誤紀錄。

## 本版訓練

`commerce_ml/train.py`，Python 3.11.3、XGBoost 3.2.0、CPU 4 執行緒；TF-IDF 只擬合訓練集，8,000 文字特徵＋14 數值特徵，原五分類特徵契約保持不變。保存 600 輪，純模型訓練 714.23 秒。類別平衡並依正常路由重新加權，沒有用複製重複樣本補數量。

## 不能過度宣稱的部分

模型單獨對診斷攻擊只命中 15/39，其他由規則補足。模型只取 content-type header，其餘 header 主要靠規則。模型仍可能對未知情境誤判或漏判，這次的零誤報只代表上述範圍。高五分類分數主要來自同家族、合成資料，且舊測試已用於診斷，不能當作完全未參與開發的最終泛化成績。

訓練報告的 rules 指標是原凍結基準規則；實際服務請看 regression.json、previous-pool-regression.json、reserved-result.json。v6／v7 已因整合或回歸問題淘汰，沒有取代正式服務。訓練器 bundle 的 validated_for_deployment=false 是訓練階段未驗收標記；外部驗收與實際部署須看獨立紀錄，不能僅靠訓練器輸出自動批准部署。
