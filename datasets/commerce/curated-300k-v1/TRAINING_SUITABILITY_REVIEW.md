# 三十萬筆資料的 XGBoost 訓練適用性審查

日期：2026-09-23。對象：curated-300k-v1/requests.jsonl，共 300,000 筆。逐筆讀取的 SHA-256 與生成驗證紀錄一致；未修改資料、未訓練分類器、未發送 HTTP 請求。

**結論：適合當作管線驗證及可篩選的合成訓練候選集；目前不適合作為唯一正式訓練集、獨立測試集，或直接支撐部署準確率的證據。**

## 適合的原因

1. JSONL 格式一致，request 與答案 label 分開，五類各 60,000 筆。可用來測試載入、標籤編碼、批次特徵抽取、模型匯出與評估圖表流程。
2. 保留 method、path、query、headers、原始 body，具備後續重新設計文字／結構特徵的材料；不是只剩一個人為分數。
3. 包含多種輸入位置、巢狀物件／陣列、多語言正常文字及攻擊語法，可作為攻擊簽章與解析器的測試素材。
4. 有 template_family、版本化生成程式、種子、雜湊及格式檢查，可追查與做較保守的分組。但家族標記本身不等於充分獨立的情境。
5. 已做完整、正規化及啟發式結構排重，避免部分粗糙的資料複製；資料不綁定訓練電腦路徑。

## 不適合直接正式訓練／評估的原因

### 1. 目標與現有推論契約不一致

model/commerce/features.json 仍指定 binary:logistic。services/commerce/detection.py 也只允許這個目標及 12 特徵，回傳單一機率。五類資料不是現有介面可直接載入的五類模型。

若要辨識五類，需要版本化多分類模型契約、固定 label-to-index 映射，以及多類機率與戰情室輸出；若只訓練正常／攻擊，才可把四類攻擊合併成二分類答案。XGBoost 原生多分類可使用 multi:softprob 並設定 num_class=5，但這只是模型設定，不會自動補齊整個推論流程。

官方參考：https://xgboost.readthedocs.io/en/stable/parameter.html

### 2. 數量不等於獨立資訊量

移除八種選填 metadata 並套用既有結構指紋後，共 33,483 個核心群組；同一核心最多 209 筆。大量資料差異來自背景欄位組合，而非新的辨識訊號。

本次另做固定 SHA-256(sample_id) 的近似 70/15/15 按行分割診斷（沒有實際建立訓練集）：

- 測試部分：45,127 筆。
- 其中 41,509 筆與訓練部分共用核心群組，即 **91.98%**。

這表示直接按行切分很容易讓模型在測試時遇到熟悉模板。此群組是啟發式，不是形式化的語意等價；此數字也不是模型準確率。

需要先按家族與近似群組切分，再只對訓練部分 fit TF-IDF／其他轉換；測試資料不得參與選參數。另保留獨立實際操作測試集。

官方參考：https://scikit-learn.org/1.8/common_pitfalls.html

### 3. 現有特徵不足以表達全部分類差異

資料沒有工作階段／時間序列，無法還原 request_count_60s 與 interval_ms；不得用檔案行序、生成速度或隨機值假造這兩個特徵。

本次對每筆清空 Detector 歷史，只執行現有規則與特徵處理，並在分析時排除兩個時間特徵。剩餘 10 個靜態特徵：

- 形成 282,205 個不同特徵向量。
- 其中 3,385 個向量同時對應不同 label。
- **20,044 筆資料**落在這些跨標籤群組。
- 只依這 10 個特徵的確定性分類器，對這批資料至少存在 9,612 筆不可同時判對的樣本。

這是特徵不可區分性的診斷，不是 XGBoost 訓練結果。其他沒有碰撞的向量也不代表具有泛化能力。不能因此假設只增加樹數或資料量就能解決。

建議共用版本化請求解析器，評估 TF-IDF／字元 n-gram 加結構特徵，再以分組驗證選擇；不要盲目追求特徵數量。session 特徵應等有真實採集資訊後再使用。

### 4. 正常流量分布不足且不自然

- 全資料 276,521 筆為 POST，即 **92.17%**。
- 正常資料的 GET 僅 4,617／60,000；沒有正常首頁、靜態資源或完整下單序列。
- 正常會員註冊只有 1 筆；登入、建立支付流程、完成訂單及讀取訂單樣本為 0。
- 203,129 筆含 PLACEHOLDER（**67.71%**），沒有對應真實資源狀態。
- 4,943 筆正常資料的頂層 first_name／last_name 超過 40 字元；抽查可見完整送貨／換貨句子放在姓名欄位。這是代表性問題，不宣稱超過 40 字元一定非法。

例如 commerce-100k-new-002254 將 "Please keep the gift message blank; the recipient will write it." 放進姓名欄位。這類資料可以是無攻擊意圖的輸入，但不能當成自然買家分布。

應補齊實際瀏覽、搜尋、登入、地址、加入／移除商品、配送、付款、完成／查詢訂單、正常錯誤與重試。以實際測試環境取得的資源 ID 建立可操作樣本，而非只複製任意自由文字到所有字串欄位。

### 5. 存在可學習的合成捷徑

原始 body 中出現非 ASCII 字元的樣本：normal 11,035 筆，四種攻擊類都是 0。包含 probe 标記的請求：normal 0，SQLi 7,019、XSS 6,194、CMDi 5,443。這些差異可能讓模型依賴語言／生成標記，未必是在學攻擊機制。

計數是原始 body，部分 Unicode 會被 JSON escape，因此不是完整語言偵測。也未宣稱已訓練出利用這些捷徑的模型。

應讓正常與攻擊共用真實背景分布，加入合法含 probe 等詞的情境、在正常多語言內容中插入明確攻擊的測試案例，並用消融實驗檢查哪些特徵在支撐成績。

sample_id 是按類別分段產生的編號，template_family 亦含類別名稱；這兩者和 label 絕不可拼入模型輸入。

### 6. 標籤可信度與端點上下文尚未驗證

標籤由生成模板指定，並非獨立逐筆審核。任意 metadata、Referer 或 filename 參數不一定會被 Medusa 執行或顯示；請求也可能在認證／欄位驗證時就被拒絕。

攻擊嘗試不需要成功才算攻擊，但仍需確認內容、標籤與測試意圖一致。不能只依字詞或生成模板名把含程式碼的所有文字判為攻擊。需要抽樣人工審核、實際 schema 驗證與安全本機回放；HTTP 200／400／500 本身不能當攻擊答案。

### 7. 規則命中數不是充分的攻擊特徵

本次使用實際 Detector、沒有載入 XGBoost，逐筆量測現有任一規則是否判為可疑：

| label | 命中／60,000 | 比例 |
|---|---:|---:|
| normal | 0 | 0.00% |
| sqli | 15,280 | 25.47% |
| xss | 29,702 | 49.50% |
| cmdi | 8,658 | 14.43% |
| path_traversal | 46,593 | 77.66% |

這只是規則對「生成標籤」的覆蓋，不是 XGBoost 準確率，也不是正式網站表現。沒有命中規則不等於資料標錯；但它顯示 rule_hits 不能替代對內容的特徵表達。normal 的 0 誤報也不能外推成真實買家零誤報。

## 建議順序

1. 暫停靠組合繼續加量，保留本批作為候選池。
2. 按核心群組／家族抽樣，先建立規模較小、人工確認且端點合理的版本；必要時每組限額或設定訓練權重，避免模板支配模型。
3. 補正常完整操作及困難正常樣本，對各攻擊類抽查內容與上下文。
4. 固定五類標籤與新的特徵契約，解決兩個不存在的時間特徵，讓訓練／推論共用處理程式。
5. 群組切分後訓練，分別比較規則、模型、兩者結合；報告 Macro-F1、各類 recall、正常誤報與攻擊漏判。
6. 最終成績以獨立實際操作測試集為主，合成測試成績另列。
